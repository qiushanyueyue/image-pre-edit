# 图片预编辑器修复设计

**日期：** 2026-04-16

## 目标

修复当前 AI 修图图片预处理项目中的四个核心问题：

1. 箭头工具的起点不能落在参考图上。
2. 文本编辑要改成类 PPT 的画布内文本框，并支持再次拖拽调整大小。
3. 视觉分析接口改为调用 `gemma4:e4b`，服务地址为 `http://yytianjin.yyboxdns.com:12524/`。
4. `JSON` 输出改成可反推文生图的中文结构化描述。

## 当前问题

- 前端画布编辑集中在 `frontend/src/components/Canvas/ImageCanvas.tsx`，箭头与矩形/圆共用拖拽起笔逻辑，未区分底图命中。
- 文本新增和编辑依赖 `TextModal.tsx` 弹窗，文本对象本身只有拖动能力，没有文本框概念。
- 线上实际部署入口是 `api/index.py`，仍在使用 Gemini SDK 与 `gemini-flash-latest`。
- 现有 `mode=json` 返回的只是尺寸加一段描述文本，不具备复用价值。

## 设计方案

### 1. 画布交互

- 保留 Konva 作为画布层实现，不整体重写编辑器。
- 增加底图命中判断函数：当工具为箭头时，仅允许在底图边界之外起笔。
- 文本从“弹窗输入”改为“拖出文本框再原位编辑”：
  - 使用拖拽生成文本框矩形范围。
  - 在画布容器上渲染 HTML `textarea` 覆盖层完成编辑。
  - 文字对象选中后使用 `Transformer` 调整宽高，文本自动按新尺寸重排。

### 2. 数据模型

- 为画布元素增加稳定 `id`，至少覆盖 `arrow` 与 `text`。
- 文本元素扩展字段：`width`、`height`、`fontSize`、`padding`、`align`。
- 箭头元素保留 `points`，但新增可测试的起笔约束工具函数。

### 3. 视觉分析与 JSON

- 统一把 AI 入口改成 HTTP 调用，环境变量改为：
  - `VISION_API_BASE_URL`
  - `VISION_MODEL_NAME`
- 默认值分别指向：
  - `http://yytianjin.yyboxdns.com:12524`
  - `gemma4:e4b`
- `mode=json` 输出改成中文字段的可反推图像描述，重点包括：
  - `图片尺寸`
  - `画面主体`
  - `场景环境`
  - `构图方式`
  - `镜头视角`
  - `景别`
  - `光线与时间`
  - `色彩方案`
  - `材质与细节`
  - `风格特征`
  - `空间层次`
  - `氛围关键词`
  - `避免元素`
  - `推荐生成提示词`

### 4. 兼容与部署

- 保持前端仍请求 `/api/ai-analyze`，不改 Vercel 路由结构。
- 优先修改 `api/index.py`，并同步 `backend/main.py` 以保证本地与线上一致。
- 更新 README / 环境变量示例，避免后续部署仍按 Gemini 配置。

## 测试策略

- 为箭头起笔限制与文本框尺寸计算提取纯函数并做前端单元测试。
- 为中文 JSON 清洗与提示词构造增加后端单元测试。
- 最终验证至少覆盖：
  - 前端 `lint`
  - 前端 `build`
  - 前端单元测试
  - 后端单元测试 / 语法检查
